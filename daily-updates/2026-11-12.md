## TL;DR

1. **`shanselman/sandbox-mcp` 416★, 20 forks, 0 open issues, MIT, created
   2026-11-06, pushed today.** A disposable **real Windows 11 VM** per agent
   run: boot, deploy, drive the UI, capture evidence, destroy. The README's
   own framing is the useful part — *"Not your desktop. Not a container
   pretending to be Windows."* Measured GUI samples run 40–50s end to end.
   The demo it leads with is the honest one: `NativeProof.exe` fails on a
   fresh network-off guest in 29.8s with `exited with code -1073741515;
   Missing dependency: VC++ redistributable`, a class of bug that every
   container-based "works on my machine" check misses because the image
   carries the redistributable.

2. **The design decision worth stealing: the CLI is the product, MCP is the
   adapter.** `sbx` runs standalone; MCP is explicitly optional ("configure
   the optional MCP adapter only if my agent needs that interface"). This is
   the inverse of most of this week's agent tooling, which ships an MCP server
   that shells out to a binary and calls the wrapper the product. The
   consequence is real: an operator can debug it in a terminal without an
   agent in the loop, and an agent that loses its MCP connection still has a
   working command surface.

3. **`qybaihe/bla` 5,407★ / 656 forks, MIT, created 2026-10-25, 2 open issues,
   pushed today.** A "blind LLM agents" defence shield: 31 MCP tools that
   poison binaries and exhaust agent context so that AI reverse-engineering
   pipelines (`morluto/rea`, autonomous decompilers) give up. It advertises
   verified results across 14 benchmark targets against a named real tool.
   Fork ratio 12% — people are running it, not just starring it. Note the
   framing war: `pktq/lasik` (112★) pitches itself as the counter, *"BLA
   blinds your agent. LASIK gives it its sight back."* Two niche repos on
   opposite sides of a two-day-old arms race is a signal about the niche
   (binary RE), not about either tool's value.

## What this means for our repos

Both shipped defects today came from the same place: **a test that passes
because the environment happens to be right.**

- `tiny-router` v0.9.2 — the path-redaction sidecar returned a working
  middleware that forwarded `req.path` verbatim when `tiny_secret_mask` was
  absent. Green suite, leaking paths. The header sidecar had already been
  fixed; the path sidecar was missed in the same pass.
- `tiny-validator` v0.7.1 — `to_json_schema()` emitted defaulted fields in
  `required`, so the exported OpenAPI/MCP schema rejected payloads the library
  accepts. Green suite, broken export.

Neither was catchable by adding more assertions about the happy path. Both
were caught by asking the opposite question: **what does this do when the
dependency is missing, and does a third-party consumer agree with my
validator?** The second is a one-line `jsonschema.validate()` cross-check and
it is now a permanent test.
