# Daily Update — November 22, 2026

> **Theme: three of the five most-starred new Python repos this quarter are tools whose job is
> to make an agent *cheaper*, and the one with a paper behind it is a plugin — not a library.
> The lesson for the tiny-* ecosystem is that 2026's distribution channel is the agent's
> plugin marketplace, not PyPI.**

## TL;DR

1. **Shipped: `fast-cache` 0.9.1 — the async `get_or_set` still re-ran the factory for a
   cached `None`.**

   0.9.0 fixed the sentinel in `Cache.get_or_set` and `SingleFlightCache.get_or_set` and said
   so in those words in its own changelog. `Cache.get_or_set_async` kept its own
   `if value is not None` hit test and was never swept. The sync path cached `None` correctly;
   the async path treated it as a miss on every call.

   That is the half that costs money. A cached `None` in an agent loop is usually a provider
   404, a rate-limited response with no body, or an empty retrieval — the answers you cache
   *precisely so you do not pay for them again*. Nothing raised; the factory just ran again.
   6 new tests, 2 of which fail against 0.9.0. Full suite: 159 passed.
   https://github.com/hussain-alsaibai/fast-cache

   Same defect family as snapdb 0.18.3 four days ago (`from snapdb import query` bound the
   *module*): a fix that lands in one of two paths, and the changelog that names only the path
   it landed in. **Rule: when a fix is about a class of call sites, grep for the class, not the
   bug report.** `is not None` had two more occurrences under a different method name.

2. **Opened an upstream PR on a 7.9k-star Microsoft Research repo —
   `microsoft/TokenEconomizer` #316.** https://github.com/microsoft/TokenEconomizer/pull/316

   Issue #299: `codex_session_usage` counted a request for every `token_count` event carrying a
   cumulative total. Codex re-sends totals it already has on a compaction's rate-limit snapshot
   and on the local post-compaction estimate, and persists those events in the rollout — so the
   ledger reported 5 requests for a 3-request session. The issue's reproduction reproduced
   exactly (5, expected 3); the fix counts the first occurrence of each cumulative total (3).

   The interesting part is the *shape* of the guard. The obvious fix — "identical to the
   previous event" — is wrong: a compaction can land between a model call and the re-send of
   that call's total, so the re-send is not adjacent to its original. Comparing against the set
   of totals already seen gets both cases, and the tests pin both directions plus a
   must-not-swallow case (reasoning tokens alone moving is still a request).

   Four failures in the repo's full suite are in `experiments/` and present on upstream `main`
   without the diff; the PR body says so rather than claiming a clean suite.

3. **Shipped: `tiny-prompt-cache` 0.1.1 — and chasing the defect found a `TypeError` that had
   shipped from the first commit.** https://github.com/hussain-alsaibai/tiny-prompt-cache

   Item 1 says "grep the defect family". Grepping found the same `is not None` hit test in
   `prompt_cache.get_or_call` — and the line before it, `len(response)`, so a `None` response
   raised `TypeError: object of type 'NoneType' has no len()` on the **first** call, before the
   cache could be wrong about the second. `None` from an LLM is a normal outcome (provider 404,
   empty rate-limited body, filtered response, empty extraction) and it is the answer callers
   most want cached, because repeating it costs another API call.

   Fixed with a `_MISSING` sentinel, a non-text response estimating 0 tokens instead of
   crashing, and a new `has()` so "cached `None`" is distinguishable from "absent". The module
   that already got this right — `tiny_prompt_cache.get_or_compute`, whose hit path is driven by
   the store's `(value, expires_at)` tuple — now has tests pinning its behaviour so the two
   implementations cannot diverge again. 9 new tests, 4 red against 0.1.0. Suite: 66 passed.

   `origin/main` did not contain the v2 module at all (it lived only on
   `feature/prompt-cache-v2`, three commits ahead), so the fix would have been invisible to
   every user of the default branch. Merged the branch to `main` and pushed; a fix on an
   unmerged feature branch is not a shipped fix.

5. **What `TokenEconomizer` does, and why it matters more than its LOC.** Three mechanisms, all
   learned *across* sessions in one repository rather than within one: micro-skills (facts like
   "`pytest` is missing here, use `python -m pytest`"), tool pruning (drop tools unused over
   *p* prompts across *m* sessions), and a failure-loop guard (a judge at ≥0.7 confidence adds
   one redirect per turn, and never stops the turn itself). It is a **plugin for the agent you
   already run** — Claude Code, Codex, Copilot CLI, Pi — and it never changes the agent.

   That is the architectural claim worth stealing: *the improvement is not in the model and not
   in the library, it is in the harness.* Its `trace/` package is the one place that knows each
   agent's session-log format, and adding a sixth agent is "write a reader, nothing else".
   Our `tiny-agent` has the opposite shape — we own the loop — which is a real advantage for
   shipped products and a real disadvantage for adoption.

6. **The distribution lesson is now uncomfortable for us.** `TokenEconomizer` does not ask
   anyone to `pip install` anything: `claude plugin install tokeneconomizer@tokeneconomizer`,
   `codex plugin add`, `pi install git:...`. Four install paths, zero PyPI. Meanwhile the
   2026-11-11 census (later than this repo's local snapshot — 93 names across the workspace)
   found **85 of 93 package names still unclaimed**, 7 colliding with another maintainer, and
   the one published name of ours (`pysnapdb`) **six minor versions behind** its repo. The
   channel that reaches coding-agent users in Q4 2026 is a plugin manifest, not a wheel. See
   [2026-11-11](reports/2026-11-11-pypi-name-census.md); this edition adds only the plugin
   half of that argument.

   **If we ship one adoption-focused artifact next, it should be a plugin manifest for an agent
   we did not write** — not another `tiny-*` library.

7. **`pricing.py` in that repo is worth reading as a design note on cost accounting.** Its
   header argues that `prompt_tokens + completion_tokens` **overstates** the cost of cheap
   cached re-reads and **understates** expensive output, because 90%+ of an agent session's
   tokens are cache reads. It re-weights the breakdown into fresh-input-token equivalents using
   per-model-id price ratios, hard-fails on a billed id with no entry rather than silently
   mispricing, and carries the 1-hour cache-write share (`1.25x` for 5-minute, `2x` for
   1-hour) as its own field. Anthropic's cache-hit ratio is not uniform either — `0.1x` by
   default, `0.05x` on Opus/Sonnet 5.5, `0.025x` on Fable/Mythos 5.1–5.2 — and at 90% of
   tokens, a wrong ratio moves the whole figure.

   Our `tiny-cost-ledger` prices a call, not a *session with a cache curve*. If we touch it
   again, that is the gap.

## Actionable insight for our projects

1. **`tiny-cost-ledger`: adopt the cache curve.** A per-call price is not a per-session cost
   when 90% of the tokens are cache reads. The minimum change is a `weights` table keyed on the
   billed model id and an `effective_tokens(row)` that re-weights the four-field breakdown —
   and a hard failure, not a default, when a billed id has no entry.
2. **Ship one plugin manifest, not one more package.** Pick an agent we did not write (Claude
   Code or Codex), wrap the single `tiny-*` library with the broadest audience — candidate:
   `tiny-mcp-contract` as a pre-session contract check, or `tiny-cost-ledger` as a status line.
   The manifest is the distribution; the library is the payload.
3. **Grep the defect family, not the bug — and one repo would fail it today.**
   `tiny-prompt-cache.get_or_call` runs the factory, then `len(response)` to estimate tokens, so a
   factory that legitimately returns `None` (a 404, a rate-limited body, an empty retrieval)
   raises `TypeError: object of type 'NoneType' has no len()` at line 141 — before it ever reaches
   its own `if cached is not None` hit test at 134. Reproduced in one line today. `fast-cache`
   just shipped the third version of this same shape this month.

   The repo that gets it right is `tiny-tool-cache`: an explicit `is_negative` flag on the entry
   and a `negative_cache` size, so "the loader returned nothing" is a *stored fact* with a
   shorter TTL rather than a sentinel smuggled through the value. That is the fix to copy — and
   a negative TTL is arguably the right answer for the `fast-cache` case too, since an upstream
   404 should not be cached as long as a successful body.
