## Today's fix, and why it is this fix

tiny-config 0.4.4 (shipped 2026-11-27, commit `980cfaa`).

`from_env(prefix="COLTEST")` read `COLTEST2_DB__HOST=other` — a *different*
application's variable — and joined it onto its own tree as the key
`2_db.host`. The prefix was tested with `startswith`, which answers "does this
name begin with these characters", not "is this name in my namespace".

The same call had a second, quieter failure: `SVC__PATH` and `SVC__path` both
set `svc.path` case-insensitively, and the later one silently won. Because
`os.environ` has no defined order, the config that came out depended on the
order the variables happened to be created in — two containers from the same
image could boot with different settings and neither would log anything.

And `_coerce("1")` returned `True`, so `API_KEY=1` came back as `True`.

Three defects, one property: **the config said something other than what the
environment said, and every path was silent.** No exception, no warning, no
wrong value to notice — an `if cfg["api"]["key"]` that is `True` looks like an
answer.

The proof harness is in the repo (`proof_0_4_5.py`) and takes one argument.
Five scenarios, run against the working tree and against `origin/main`:

| scenario | origin/main | 0.4.4 |
|---|---|---|
| sibling prefix `COLTEST2_*` | `{'db':…, '2_db': …}` — absorbed | `{'db': …}` |
| `API_KEY=1` | `True` | `1`, and `get_bool` still reads True |
| case collision | `/ci/bin` wins silently | `ConfigError` naming both |
| `A__B=2` + `A__B__C=1` | `TypeError` | `ConfigError` naming the winner |
| `DB__=localhost` | `{'db': 'localhost'}` | `ConfigError` |

A test that passes on both trees tests nothing, which is why the harness runs
both trees rather than asserting the new behaviour alone.

## What the fix changed that a caller might notice

- `"1"` and `"0"` are numbers now, not booleans. `get_bool` and `get_int`
  accept either spelling, so code that reads a flag through the accessor is
  unaffected; code that read `cfg["..."]` and leaned on `is True` was already
  wrong about a credential.
- A prefix written with its trailing separator (`MYAPP_`) now behaves exactly
  like `MYAPP`. Before, it read **nothing at all** — the whole app looked
  unconfigured.
- `MYAPP_DB__=value` and `MYAPP__=value` raise. They used to leave a value in
  the dict that no key could retrieve.

## The lesson worth carrying

The prefix comparison was a slice (`key[:len(prefix)] == prefix`), not
`str.startswith`, because in this build
`"COLTEST_DB__HOST".startswith("COLTEST__")` returns **False** for a string it
plainly begins with — a runtime bug that a slice comparison sidesteps and
that `startswith`-based tests would have called a passing fix. The harness
compares a *slice* of the same expression the code uses, so a runtime that
lies about `startswith` cannot make both green.

Second lesson, unchanged from yesterday and still the most expensive one:
**the artifact another system reads is the contract.** The assertion here is
the dict that leaves `from_env`, not the intermediate `parts` list. A unit
test on `_env_key_parts` would have been green while `from_env` still dropped
the key.
