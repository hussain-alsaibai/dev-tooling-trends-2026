## Actionable insight

Every one of these tools ships a **packed binary, a proxy, or a runtime** that
sits between the developer and the model, and **none publish a verifiable
manifest of what the artifact contains**. `rtk`'s own open issues are version-
and state-accounting bugs. The gap we can fill cheaply: a `tiny-dist-audit`
companion that emits a signed, reproducible manifest (file hashes + a
`pip download`-style provenance block) for release artifacts, and a GitHub
Action that diffs it per tag. That is a weekend of work on top of what we
already have, and it is the same shape as the MCP contract-diff bet.
