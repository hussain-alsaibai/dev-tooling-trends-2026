# Daily Update — November 13, 2026

> **Theme: the token bill is now the product. Compressing what reaches the
> model outranks adding another MCP server, and the one real bounty found this
> week is a correctness bet on a big repo, not an escrow template.**

## TL;DR

1. **`headroomlabs-ai/headroom` 79,508★ / 6,223 forks, created 2026-01-07,
   pushed 2026-11-12.** Compress tool outputs, logs, files and RAG chunks
   *before* they reach the LLM: it claims ~20% fewer tokens for coding agents
   and 60-95% on log/RAG payloads. The 8% fork ratio is the interesting number
   — people are forking it, not just starring it. This is the same problem
   `tiny-context-optimizer` was built for, which makes it a direct comparison
   target rather than a competitor to ignore.

2. **`lexmount/moli` 23,581★, published 2026-11-13, Rust.** A headless browser
   built for agents — "lite, fast, high-compatibility". Check before relying
   on it: the repo is 8 months old but the version history is thin, so the
   star count has run well ahead of any independent validation. My browser
   automation still goes through Playwright/Browserless; moli is worth a
   benchmark, not a migration.

3. **MCP leaders moved but nothing broke.** `microsoft/playwright-mcp`
   39,571★, `v0.0.85` on 2026-11-09. `github/github-mcp-server` 34,421★,
   `v2.1.0` on 2026-11-03. `PrefectHQ/fastmcp` 28,404★, now `v4.2.0a5`
   (2026-11-13) with a **Python floor of 3.11** as of a4 and a new
   `SkillManifestProvider` that serves skills from frontmatter + digest and
   reads a file only when a client requests it — no re-hashing every file per
   request. If our own MCP servers pin fastmcp, that floor is a breaking
   change, not a patch.

4. **The only credible bounty found this week: `tenstorrent/tt-metal` #65437,
   $2,000, "Restore OpenVLA execution and action correctness"**, opened
   2026-11-12, 2 comments. Different shape from the escrow templates: a real
   repo (7,855 open issues, pushed today) with a concrete defect list — missing
   SigLIP positional embeddings, unmapped Q/K weights, and an off-by-one in the
   action-token sequence including the prefill token. Success is one PR plus
   regression tests checked against a Hugging Face reference with agreed
   numeric tolerances. It needs a Wormhole N150 to run end to end, which is
   why it is not a candidate for us: the hardware is the gate, not the code.

5. **The escrow feed stayed a trap.** The same `IES-BoilerRoom` org that posted
   yesterday's fake `$600` now has two new repos created **2026-11-12** with
   0 stars, 0 forks and four escrowed bounties ($450/$600 × 2). Same
   `bounty-plaza` mirroring. Checked first, as always: org age, star/fork
   ratio, whether the issue accepts human PRs, and whether the named escrow
   rail can confirm the money exists.

## Insight

**The bottleneck moved from context *window* to context *bill*.** Both the
top new repo (headroom: shrink what reaches the model) and the fastmcp change
(don't re-hash what a client hasn't asked for) are the same optimisation
applied at different layers: stop paying for bytes nobody reads. Our own
servers and reports should be measured on the same axis — the `repo_health_check`
style generators already write only at the end, and the payload they emit is
read by one consumer, so trimming it is safe work with a measurable return.
