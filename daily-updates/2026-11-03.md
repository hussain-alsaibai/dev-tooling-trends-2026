Audited all **37** Python packages in `repos/`: **4 published, 33 not**. The 33 404 on PyPI. And the 4 that did ship get **4–13 downloads per month**. Meanwhile `context-mode` — the same category of tool — does **37,976 downloads/week**.

Only **snapdb** has a publish workflow (`.github/workflows/release.yml`). The other three were pushed by hand, and the hand-pushes are the reason their versions are still `0.1.0`.

**Rule: a package that is not on PyPI cannot be discovered, and a package with no release workflow cannot be trusted to stay published.** The cheapest fix is one workflow per repo (`pypa/gh-action-pypi-publish` with trusted publishing, no long-lived token) and a tag-triggered release. Start with `tiny-context` and `fast-cache` — both solve a problem `context-mode` proves is real, and both are zero-dependency, which is the differentiator `context-mode` (MIT/ELv2, npm) does not have.

**Second rule: our differentiation should be the thing they lack — no runtime, no npm, no vendor.** `context-mode` needs Node 22+ and a native gateway plugin; `claude-mem` needs a worker and an AI provider. `tiny-context` is a 14 KB zero-dependency Python file. Same problem, different deployment.
