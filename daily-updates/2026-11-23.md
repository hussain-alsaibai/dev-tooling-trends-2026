# Daily Update — November 23, 2026

> **Theme: the most common failure in this ecosystem is not a broken library, it is a
> correct library whose *absence* breaks something else. Two of today's three signals
> are optional-or-absent dependencies; both were found in our own tree first.**

## TL;DR

1. **Shipped: `snapdb` 0.18.4 — a `DocumentStore` whose first document lacked a field
   dropped that field from every later insert, silently.**
   https://github.com/hussain-alsaibai/snapdb

   `_coerce` built its field map from record one and coerced everything after it against
   that map. `insert({"text": ..., "ts": 3})` into a store whose first record was
   `{"text": ...}` wrote the text and discarded `ts`. No error, no warning, no way to
   notice until a report came back missing a column.

   Widening it is not an assignment. The row layout is positional
   (`offset = idx * row_width`) and a slab decodes with the schema object it was built
   with, so re-opening with a wider `Schema` reads rows from the wrong offsets. New
   public API `SnapDB.replace_schema(new_schema)` rewrites header + live rows at the new
   width, and it survives close/reopen.

   The second half is the honest one: pre-widening rows were re-encoded with the type
   default, so a new `ts` column claimed **every legacy record happened at the unix
   epoch**. Nullable columns now store an empty slot that decodes to a *missing key*, so
   "no value recorded" is distinguishable from "the value was 0". Absence sorts last in
   both directions, and `sort` finally runs before `limit`/`offset` — it had been slicing
   the unsorted scan. 14 new tests; 259 passed / 27 skipped on 3.8 and 3.10.

   **Rule: an absent value and a zero are different facts, and a fixed-width row hides
   the difference.** If a column can be widened after rows exist, the placeholder *is*
   the API.

2. **Shipped: `tiny-router` 0.9.4 — an optional dependency that was absent turned 16
   skipped tests into 1 collection error.**
   https://github.com/hussain-alsaibai/tiny-router

   `test_v074_redact_headers.py` did a bare `import tiny_secret_mask` at module scope.
   `tiny-secret-mask` is an *optional* sidecar — `pip install tiny-router` does not bring
   it — so on any machine without it pytest aborted the file and reported the suite as
   broken. Every test in that file that did not need the dependency never ran, including
   the test that asserts a redaction layer without its masker must RAISE.

   Also fixed: redaction availability was computed once at import and never re-resolved,
   so an app that installed the dependency later got a stale "unavailable" (or a stale
   "available" pointing at an unusable masker). Now resolved at call time.

   CI collects by pattern instead of naming two modules, and gained a job that runs the
   suite with the dependency deliberately absent **and asserts `find_spec` is None**, so
   the skip path is exercised rather than assumed. 196 passed / 26 skipped without the
   extra, 222 passed with it; 3.8–3.14 all green.

   **Rule: `skip` is a result; a collection error is not.** If a dependency is optional,
   the tests must import without it.
